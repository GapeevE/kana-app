# kana-app — план реализации

> **Для агентов-исполнителей:** ОБЯЗАТЕЛЬНЫЙ САБ-НАВЫК: используйте superpowers:subagent-driven-development (рекомендуется) или superpowers:executing-plans для выполнения плана задача за задачей. Шаги размечены чекбоксами (`- [ ]`).

**Цель:** Веб-приложение для изучения японской азбуки русскоязычными пользователями, с интервальными повторениями по SM-2, закрытой регистрацией и синхронизацией прогресса между устройствами.

**Архитектура:** Next.js App Router на Vercel, Postgres в Neon через Drizzle. Сессия тренировки целиком выполняется в памяти клиента для мгновенного отклика; результаты уходят на сервер пачками, где SM-2 пересчитывается заново — сервер является источником истины. Ядро (`core/*`) не зависит ни от React, ни от Next.js, ни от базы, потому что переиспользуется в будущем разделе «Кандзи».

**Стек:** Next.js 16, React 19, TypeScript, Tailwind 4, shadcn/ui, Neon (Postgres), Drizzle ORM, Auth.js v5, Zustand, Zod, Vitest, pnpm.

**Спека:** [`docs/spec.md`](../../spec.md)

## Глобальные ограничения

- **Пакетный менеджер:** только `pnpm`. Не использовать npm или yarn.
- **Коммиты:** исполнитель **не создаёт коммиты самостоятельно**. Шаги «Commit» в задачах означают: сообщить владельцу продукта, что задача готова к коммиту, и передать предлагаемое сообщение. Коммит делает владелец.
- **Комментарии в коде:** минимизировать. Объяснения выносятся в `docs/`, а не в исходники.
- **E2E-тесты не запускаются.** Playwright и аналоги не устанавливаются. Тестирование интерфейса выполняет владелец продукта вручную.
- **Тесты Vitest пишутся только для `src/core/*`** — чистых функций SM-2, сборки сессии и прогрессии. UI, серверные действия и репозитории тестами не покрываются.
- **Язык интерфейса:** русский. Название в шапке и `<title>`: `kana-app`.
- **Чтение знаков:** только ромадзи в системе Хэпбёрна (`shi`, `ji`, `chi`, `tsu`). Кириллическая транскрипция в приложении не используется нигде.
- **Направление проверки:** только узнавание — приложение показывает знак, пользователь вводит чтение. Обратного направления нет.
- **Шкала quality:** 5, 4, 3, 2, 0. Значения 1 не существует.
- **Идентификаторы** (`id`, `group`, `row` в датасете) — латиница, строчные, разделитель `_`.
- **Переменные окружения:** `DATABASE_URL`, `AUTH_SECRET`, `INVITE_CODE`. Других нет.
- **Стиль кода:** TypeScript strict. Без `any` в экспортируемых сигнатурах.

## Структура плана

Задачи вынесены в отдельные файлы: [`tasks/`](tasks/README.md).

**Перед началом работы исполнитель читает [`tasks/AGENT.md`](tasks/AGENT.md)** — требования, действующие для всех задач: запрет на коммиты, запрет на E2E-тесты, правила по комментариям, технические ограничения.

| Этап | Задачи | Содержание |
|---|---|---|
| 1. Окружение и ядро | [1–6](tasks/README.md#этап-1-окружение-и-ядро) | SM-2, датасет каны, прогрессия групп, очередь сессии. Без базы данных |
| 2. Данные и доступ | [7–10](tasks/README.md#этап-2-данные-и-доступ) | Схема Neon, аутентификация, репозитории, серверные действия |
| 3. Интерфейс | [11–16](tasks/README.md#этап-3-интерфейс) | Вход, главный экран, тренировка, справочник, прогресс, деплой |
| 4. Доработка | [17](tasks/README.md#этап-4-доработка-после-первого-тестирования) | Тёмная тема, тон, иконки, исправление дефектов интерфейса |

Задача 7 заблокирована до получения `DATABASE_URL` и `INVITE_CODE` от владельца продукта. Задачи 1–6 выполняются сразу.
